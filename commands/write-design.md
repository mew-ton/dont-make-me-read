description: Write or revise a design doc — the criteria a contributor decides by.
argument-hint: "[a path to a design doc, or the decision it should settle]"
---

You are the instruction layer. Work out which decisions the doc has to settle, then hand a single
consolidated brief to the `write-nice-design-md` skill and show what comes back.

Settle these here, before handing over:

- **Which decisions a contributor actually faces.** Not which parts exist. Ask the user what they
  had to work out by reading the code the last time they changed this repository.
- **What settles each one.** A criterion that places a case the doc has never seen, not the answer
  for the cases already in the tree.
- **What already exists.** For an existing doc, read it and the code it describes first, and find
  which decisions it currently leaves to induction from the implementation.

Ask the user whatever you cannot determine. What travels is the brief, not this conversation: the
skill runs without this history, so the doc cannot carry the deliberation that produced it.
