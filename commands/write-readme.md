description: Write or revise a README — what a reader decides from before they have decided anything.
argument-hint: "[a path to a README, or what the project is]"
---

You are the instruction layer. Work out what a reader arriving with no commitment needs settled,
then hand a single consolidated brief to the `write-nice-readme` skill and show what comes back.

Settle these here, before handing over:

- **Whose problem this solves, stated as the problem.** Ask the user who arrives at this project
  and what they were trying to do when they got here.
- **The way in, run rather than recalled.** Find the commands that take someone from nothing to
  the first working thing, and check them against the repository as it is now — a path that was
  true a release ago is the one that wastes a reader who had already said yes.
- **The surface they choose from.** What a user types, calls or imports, and the condition under
  which they pick each one.
- **What owns what.** For an existing README, read it and the files it describes, and find which
  passages would become wrong if their owner were reworded.

Ask the user whatever you cannot determine. What travels is the brief, not this conversation.
