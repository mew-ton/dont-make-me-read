# Architecture

## Bird's eye view（俯瞰）

誰かが読んで行動しなければならないテキストは、行動できるようになるまでに読み手にコストを払わせる。そして
書き手にはそのコストが感じられない — 自分の下書きは、そこに欠けている文脈を自分で補いながら読むからだ。
このプラグインはそこから導かれるルールを、参照されるのを待つのではなく**書いている現場に届く**ように配置した
ものである。

重みを担うのは二つである。**入口**が構えをインストールする：適用すべきテスト、それを満たすために決して削って
はならないもの、そして手元の成果物のためのルールがどこにあるか。**成果物ごとのベストプラクティス**が、その
一種類の成果物が取る形 — セクション、予算、満たすべき条件 — を保持する。固有の形を持つに足るほど形が固定
された成果物について。

それ以外はすべて、二つ目に仕えるために存在する：テキストが何であろうと成立し、したがってあらゆる成果物の
下地として効く細かいルールと、その同じ条件を、すでに書かれたテキストに対して逆向きに走らせるもの — 書き手は
自分の下書きを judge できないからである。どちらも、それ自体の存在理由を持つ独立した関心事ではない。
ベストプラクティスが**適用され**、**チェックされる**ために必要なものである。

**ベストプラクティスはスキルが保持している。だからそのスキルは、それが judge する対象から隔離されねばならない。**
成果物について議論してきたセッションの中で走らせると、そのセッションの文脈が、標準を保持しているはずのものに
届いてしまい、標準はたった今言われたことのほうへ曲がる。だから成果物は作業セッションの**外**で生み出される —
人はコマンドから、エージェントは fork から到達する。fork が守っているのはそれであり、生み出す側のスキルが
その場で呼ばれない理由もそれである。

## Codemap（コードマップ）

レイアウトはプラグイン形式のものであり、ここが何かを発明してはいない：入口とスキルは、その形式が置く場所に
座る。スキルとは、`SKILL.md` がロードされる部分であるようなディレクトリであり、その中の他のすべてのファイル
は `SKILL.md` から参照されることで到達され、他の経路では到達されない。だからそれらのファイルが取る名前は
著者が決めてよい。

以下の見出しはすべて、貢献者が実際に直面する判断である。あなたの判断がここに無いなら、それはこのファイルの
穴であって、今日たまたまツリーに在るものから答えを帰納してよいという許可ではない。

## Cross-cutting concerns and invariants（横断的関心事と不変条件）

### The golden rule（ゴールデンルール）

**覚えておかねばならないルールは破られる。だから、それを性質にしてしまう仕掛けを作れ — そしてその仕掛けを、
誰かが取りに行かねばならない場所ではなく、書くことがすでに起きている場所に置け。**

以下のすべての判断はこれの一事例である。このファイルが名指ししていない新しい判断が現れたら、ここから導け：
何が覚えておくべきことになるのか、そしてどんな配置なら覚えておく必要がなくなるのかを問う。

### The invariants it generates（そこから生まれる不変条件）

**メニューから名指しされて到達できるスキルは無い。** ルールは、他の作業の途中で書かれるコードコメントに着地
しなければならない。名指しされたときだけ発火するものは、最も必要とされる瞬間を取り逃がす。だから、モデルが
自分の判断で選ぶことが唯一の入り口である。

**成果物を生み出すスキルは、そこに至った会話を決して見ない。** 履歴を一切持ち込まないことが、二つのものを
同時に締め出す：読み手が決して確認できない残滓と、セッションが、その出力を judge するはずの標準にかける圧力
である。どちらも、そうでなければ誰かが抵抗を覚えておかねばならないものだった。

**スキルは、その読み手には確認できないことを確認できてしまうツールを決して持たない。** ある判定が価値を持つ
のがまさに「読み手が手にするものから到達された」からである場合、それを超えるツールは、その判定を「使わないで
おくことを誰かが覚えている限り」しか健全でなくする。

### Out of scope（スコープ外）

意図的に存在しないもの。貢献者が一日かけて再発見せずに済むように：

- スキルは自分の軸だけを judge し、それ以外はしない。主張がリポジトリに接地しているか、依存が閉じているか、
  スコープが妥当か — それらは、それを呼んだ側に属する。
- 汎用の「これをレビューして」の入口はここに無い。パスは自分が適用する条件を名指しし、それについて答える。
- ツールチェーン、パッケージマネージャ、インストールパスを前提にしていない。コマンドを必要とするスキルは、
  走っているリポジトリからそれを読み出せと言う。
- 第二言語のキーワード列を持つ description は無い。公開されたスキルは利用者がどの言語で打つか知り得ない。

## Where a new entry point goes（新しい入口をどこに置くか）

**人がそれを起動すると決める → 打てるもの。すでに進行中の作業に届かねばならない → スキル。**

一つ目の不変条件を適用したものである。二つの経路は同じものの代替ではない。一方は、何かを書かせたい／
チェックさせたいと**自分で決めた**人が手を伸ばすもの。他方は、何も決めていない人に**届く**もの。

## What a command owes the skill it calls（コマンドが呼ぶ先に負うもの）

**未決着のものはすべて引き渡しの前に決着させる。渡るのは一つのブリーフ。**

同じ依頼はいくつかの形で到着する：内容がすでに書かれている／どこかに存在していて取得が要る／そもそもそれが
何であるべきかがまだ会話の途中。これを仕分けるのは実際の作業であり、そのすべてが会話である — 中途半端な依頼、
取得した資料、持ち出されては捨てられた選択肢。

その会話をそのまま渡すことは、それを**成果物が書かれる文脈**に入れることであり、成果物に表出する。先に一つに
まとめることがそれを締め出し、成果物をセッションの外で生み出すことが、それを「覚えておく」ではなく構造にする。

## What context a skill runs in（スキルがどの文脈で走るか）

**ブリーフから成果物を生み出す → セッションの外。すでにモデルの目の前にある作業に作用する → その場で。**

上の隔離の議論はこの一方向である。基準はもう一方向にも同じ強さで効く：すでに目の前にある作業に作用するスキル
を隔離すると、それが作用する対象から切り離される。ルーティングは目の前の作業を要る。書くことへの制約は、
書くことが起きる場所で起きねばならない。findings を返すパスは、根拠が付いていなければ価値ゼロの findings を
返す — 隔離すれば、誰もそのレビューをレビューできない。

これが frontmatter を決める。ここのすべてのスキル：

```yaml
user-invocable: false
disable-model-invocation: false
```

成果物を生み出すものはこれを足す：

```yaml
context: fork
background: false
```

`background: false` は、呼び出し元が同じターンで結果を見せるから。`agent` と `model` は未設定のままにする：
どちらも fork を**情報収集**の実行が必要とするものまで狭めてしまい、読み取り専用のツールセットでは、その fork
が生み出すために存在する成果物を書けない。

## What tools a skill gets（スキルがどのツールを持つか）

**自分の仕事が必要とするもの — ただし、その読み手には確認できないことを確認できてしまうものを引いた残り。**

見落としやすいのは引き算のほうであり、それが効くのは、そのスキルの価値のすべてが「どの足場から judge するか」
である場合だけである。テキストだけを手にしている者と同じやり方で判定に至らねばならないパスは、参照を解決した
りリポジトリを確認したりするものを一切与えられない。その足場こそが成果物だからである。そして取得は、それを
呼ぶ側に属することになる。そうした足場が懸かっていない場合、スキルは仕事が必要とするものを取る。

## Where an explanation goes（説明をどこに置くか）

**誰がそれを抱えねばならないか、そしてどれだけの頻度でか、で決まる。**

| その説明が | 置き場所 |
|---|---|
| 貢献者が判断に使うもの | ここ |
| スキルのすべての経路が必要とするもの | そのスキルの本文 |
| 一部の枝しか到達しないもの | そのスキルの `SKILL.md` の隣にあり、そこから指されているファイル |
| フィールドの意味 | frontmatter のどこでもない |

frontmatter は `SKILL.md` の中で唯一、読まれるのではなくパースされる部分であり、その全体が発火のたびに
ロードされる。そこに付けた末尾の `#` は、それで混乱したはずのない読み手に何も説明せず、すべての読み手が
永遠にそのコストを払う — 枝固有の詳細を一段下へ押し下げるのと同じ議論が、一段上に当てはまっているだけである。

## When an artifact earns rules of its own（成果物が固有ルールを持つのはいつか）

**その形が、一般則では供給できないほど固定されているとき：名前の付いたセクション、予算、テンプレート。**

たいていの書き物にはそんな形がなく、入口のテストと、テキストが何であろうと成立するルールで足りる。その基準を
超えていない成果物にベストプラクティスを足すと、判断すべき description がもう一つ増えた重みを以後のすべての
ターンが払い、誰も必要としなかったテンプレートを買うことになる。

## What to do when a body is over budget（本文が予算を超えたとき何をするか）

**一部の枝しか到達しないものを、その `SKILL.md` の隣のファイルへ押し出す。通るまで。**

```bash
bash skills/write-nice-skills/scripts/count-tokens.sh skills/*/SKILL.md
```

非ゼロなら、まだコミットしない。どのコードが何を意味するかはスクリプト自身のヘッダにあり、そのうち予算に
ついてのものは一つだけである — 残りはチェックが走らなかったことを言っており、それは合格ではない。本文が指す
ものには深さのルールがありサイズのルールはないので、材料は削除されるのではなく、発火のたびに全員が払う経路
から外へ移されるだけである。
