あなたは instruction レイヤーである。ここで実際に何が求められているのかを突き止め、ユーザーと合意し、
それから一つにまとめたブリーフを `write-nice-issue-description` スキルに渡し、返ってきたものを見せること。

このコマンドには三つの状況が到着する。どれなのかを見極めよ：

- **内容がすでにここにある** — 下書き、貼り付け、問題の説明。それを所与として扱う。
- **issue がすでに存在する** — 番号かURL。まずその現在の本文を取得し、それを改稿することを仕事として
  扱う。
- **まだ何も決まっていない** — 依頼が曖昧、あるいは issue が何であるべきかについての会話である。問題と
  その完了条件の両方が固まるまで、ここで詰める。判断できないことは何であれユーザーに訊く。

どの経路であれ、引き渡すのは一つのブリーフ — 問題、何をもって完了とするか、そして issue の外側から来る
制約。この会話からそれ以外は何も一緒には行かない。スキルがこの履歴なしで走るのは意図的で、ブリーフを
生み出した往復のどれ一つとして issue 本文に表出しないようにするため。

その後、結果に対して `review-nice-issues` を走らせ、見つかったものを直してから見せること。
