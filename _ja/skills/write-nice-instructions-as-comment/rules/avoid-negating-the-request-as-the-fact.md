# 依頼を否定したものを事実にしない

Title が、依頼に「〜でない」を差し込んだだけのものに読めるときは常にこれを読むこと。

「これを名前付きの computed に抽出せよ」を「名前付きの computed に抽出されていない」と書き換えたものは
チェック可能ではあるが、それでも Title の形をまとった依頼にすぎない — 求められたものの**不在**を名指しして
おり、その依頼自体以上の情報を担っていない。事実は依頼の上流に座っている：その依頼が応答しているところの、
**今日コードで起きていること**は何か？

### Bad: Title が依頼を否定しているだけ

```markdown
**minor** — `FooDetail.vue:140` embeds a compound condition directly in `v-if` (not extracted into
a named computed)
```
（訳：「`FooDetail.vue:140` は複合条件を `v-if` に直接埋め込んでいる（名前付きの computed に抽出されて
いない）」）

Title は依頼（「名前付きの computed に抽出せよ」）の極性を反転させたものであって、観測ではない —
「〜に抽出されていない」は修正が何をするかを逆向きに述べ直しているだけで、依頼そのもの以上の情報を担って
いない。（さらに、それを引き起こしたたまたまの1ファイルを融合させてもいる — これは
[`avoid-fusing-the-instance-into-the-title.md`](avoid-fusing-the-instance-into-the-title.md) が扱う、
独立した二つ目の問題である。片方を直しても、もう片方は免除されない。）

### Good: Title が、依頼が応答している振る舞いを名指しする

```markdown
**minor** — compound and complex conditional expressions are written directly in the template
```
（訳：「複合的で複雑な条件式がテンプレートに直接書かれている」）

事実は依頼の上流にある：テンプレートが実際に今日やっていること（インラインで書かれた条件）であって、
書き手が代わりに望むもの（computed への抽出）の鏡像ではない。これが、タイトル自体が依頼の反転になることなく
修正を正当化するものである。

この同じ手は、指摘が壊れているものを報告するのではなく、より良い案を提案する場合にも当てはまる：上流の
事実は「なぜコードが壊れているか」である必要はなく、「なぜコードが今日この形をしているか」でもよい —
決して、提案自身の否定であってはならない。
