# この規則がどこから来たのか、そして何がその隣に座っているのか

このファイルを指すものは何も無く、指すべきでもない：これはスキルを保守する者に向けた出自と近隣の見取り図で
あって、指摘を書くエージェントがロードしなければならない材料ではない。ここに置くことで本文の外に出せる。
本文にあれば、コメントを書きたいだけの読み手全員が代金を払うことになる。

## 近隣のスキルとの関係

これらの大半を、このスキルはもう名指ししない。名指ししても著者が次にすることが何も変わらなかったからで
ある。まだ現れているものは、それが変える手順の上にある。次にこのスキルを編集する者のために記録しておく。

- `dont-make-me-read` — このスキルが研ぎ上げるテスト：指摘は、読み手が行動する前に抱えねばならないもので
  判定される。
- `dont-make-me-read` の `rules/unverifiable-context.md` — 読み手が、その指摘の主張を確認できるか：根拠は残り、それが出てきた
  プロセスは落ちる。
- `dont-make-me-read` の `rules/reference-detours.md` — 読み手がその指摘を理解するためにどこかへ送られたか、そして代わりに使用地点で
  何を言い直してよいか。
- `write-nice-issue-description` — 問題の記述＋完了条件であり、リポジトリを読める実装者に読まれるもの。
  このスキルはあちらが始まるところで終わる：名指しできる修正がない指摘が立てる issue は、このテンプレート
  ではなくそのスキルの規則で書かれる。本文は、その issue はこのテンプレートの仕事ではないと、スキル名を
  挙げずに述べている。あちらを起動するわけではないからである。
- `write-nice-instructions-as-rule` — その指示が効力を持ち続ける場合の、同じ要求：ガイドライン、規約、
  あるいはスキル本文の中の規則。それらは、その規則が捕まえた者によって順番どおりでなく読まれる。
  description の境界が、そのスキル名を挙げずにその場合を取り戻している。

## ガードが何の記録であるか

Common Rationalizations と Red Flags は、実際に言われたこと、そして下書きの中で実際に見つかったもので
埋められている。1行は、誰かが答えねばならなかった言い訳の記録である。トークンを節約するために1行を消すこと
は、記録を消して原因を残すことである。
