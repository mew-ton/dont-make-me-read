## Scope（範囲）

ドキュメントの依存関係は、リンク先だけではない。**自分が所有していないものを、名指ししたり、数えたり、
写したり、その構造について主張したりすれば、それはすべて依存**である：そのものが変われば、このドキュメント
は誤りになり、誰かがそれに気づいて書き換えねばならない。

そのコストは書いている最中には見えない。書いた時点でその文は真だからである。コストは後から現れる — 静かに
真でなくなったドキュメントとして、あるいは誰も飛ばせない編集として。

このスキルは、ドキュメントが**何に固定されているか**を報告する。判定はしない。依存は欠陥ではない — 何にも
依存しないドキュメントは何についても何も言っていない — そして、ある依存が保守コストに見合うかは「それが何を
買っているか」についての問いであり、それを握っているのは呼び出し元であって、このスキルではない。

## What counts（何が該当するか）

| テキストが | 固定されている先 | 壊れるとき |
|---|---|---|
| 別の場所で定義された名前 | その定義 | 改名、削除、意味の移動 |
| 員数、または完全だと主張された集合 | その成員 | 何かが加わる／抜ける |
| それを所有するファイルから写した定義 | その所有者 | 所有者が変わり、この写しが変わらない |
| どう配置されているかについての主張 | その配置 | 再構成される |
| パス、リンク、行番号 | その場所 | 移動する |
| 引用した外部の出典 | 他人の判断 | 相手が改訂する、または消える |
| 翻訳、ミラー、二つ目のコピー | 原文の全体 | 原文のどこかが変わる |

報告を鋭くし、かつコストがゼロなものが二つある：

- **役割か実体か。** アーキテクチャ上の役割の名前は、今それを満たしているものより長生きする。満たしている側
  の名前はそうではない。同じ文でも保守コストが違い、呼び出し元はその span だけからは見分けられない。
- **向こう側を誰が所有しているか。** このリポジトリ内のものへの依存は、ここにいる誰かが壊れるのを見られる。
  外部の出典への依存はそうではない。

## What to return（何を返すか）

依存ごとに：その span、何に固定されているか、どんな変更で壊れるか、そして役割と実体のどちらに固定されて
いるか。span は説明せずに**引用する** — 呼び出し元が秤にかけるのは実際のその文であり、言い換えはそれ自体の
依存を持つ二つ目のコピーだからである。

見つけたものを返し、見つけなかったものについては何も言わない。「他に依存はない」と報告するパスは、持ちよう
のない網羅性を主張している。

## Common Rationalizations（よくある自己正当化）

| 自己正当化 | 実際のところ |
|---|---|
| 「依存はリンクだけだ。あとはただの散文だ。」 | 名前とは、読み手がクリックできず、保守する者が grep もできないリンクである。同じように壊れ、壊れたことをより告げない。 |
| 「今は正確なのだから問題ない。」 | すべての依存は、書かれた時点では正確だった。秤にかけているのは、それが正確でなくなる日に何が起きるかである。 |
| 「これだけ列挙したらノイズになる。」 | その一覧こそが findings である。ある項目が対処に値するかは呼び出し元の判断であり、あなたが濾し取った項目については彼らは判断できない。 |
| 「これは明らかに問題ないので、外しておく。」 | 「明らかに問題ない」は判定である。報告して、呼び出し元に同意させよ。 |
| 「ドキュメントの残りはきれいだと書き添えておく。」 | あなたが確認したものを確認しただけである。網羅性の主張はそれ自体が依存である — あなた自身の徹底ぶりへの依存であり、後から誰にも検証できない。 |
