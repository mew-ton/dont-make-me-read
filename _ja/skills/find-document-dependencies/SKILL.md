## Overview（概要）

このスキルは、あるドキュメントが書き換えられねばならなくなる原因のすべてをグラフとして返す — 何が何に
固定されているか、どちら側が動かねばならないか、どれだけ大きな音を立てて壊れるか — そしてそのどれも
判定しない。誰も描かなかった依存は、誰かが後でさせられる編集であり、しかもその人が見ていなかった
ファイルの中にある。

## How to work（どう進めるか）

- **読む労力はポインタではなく散文に使う。** リンクをチェックするものが何であれ、弱いほうについては
  すでにあなたより優れている：通りすがりに見た弱い依存は報告し、それを狩りに行かない。
- **すでに読んでいる span には両方の判定をつける。** 割に合わなかったのは、弱いものを狩りに行くこと
  だけである。
- **span は引用する。決して言い換えない。** 呼び出し元が秤にかけるのは実際のその文であり、言い換えは
  それ自体の依存を持つ二つ目のコピーだからである。

## What a dependency is（依存とは何か）

二つのテキストは、**一方を直したらもう一方も直さねばならない**、さもなくば矛盾するという関係にあるとき、
依存関係にある。リンクはその一つの形であり、最も見つけやすい形である。

## Direction（向き）

矢印で書く：**A → B は「A を直せば B も直さねばならない」を意味する。** 動かねばならないのは B の側で
あり、span の形はどちら側なのかを教えてくれない。

二つのテキストの間で、矢印はどちらの向きにも走りうるし、両方向に走ることもある。

- **片方向。** A → B があり、B → A はない。B が A を記述しており、A は B を気にせず動ける。見つかるものの
  大半はこれで、矢印そのものが findings である：二つのうちどちらが腐るのか、したがってどちらを読み手が
  信じてよいのかを述べているからだ。
- **両方向。** A → B と B → A の両方がある。どちらも単独では編集できないので、それは二つのファイル名を
  着た一つのものである — 片方向の辺を二本並べたものとは別の項目であり、別の対処になる。日常的にあるのは、
  同じ計画を二つのシステムが持っている場合だ：開発者が作業に使うトラッカーと、スケジュールを立てている
  ページが、互いを言い直している。どちらを編集してももう一方が誤りになり、どちらのシステムからもそれが
  起きたことは見えない。

名前についていえば、矢印の向きが、ドキュメントの定義する役割と今それを満たしている実体との違いのすべて
である。同じ文で、保守コストは正反対になる。

## Strength（強さ）

| | 弱 | 強 |
|---|---|---|
| 何に固定されているか | 向こう側が**どこにあるか** | 向こう側が**何を言っているか** |
| 形 | ポインタ：リンク、パス、issue 番号、引用 | 散文：名前、記述、向こう側が持っている内容の言い直し |
| 壊れるとき | 向こう側が移動する | 向こう側の内容が変わる |
| 直し方 | 指し直す。それに読み手はたいてい自力でも辿り着けた | 書き直す：その文は今や真でないことを述べている |
| どう見つかるか | 機械的に。リンクチェッカがひとつ残らず見つける | 読むことによって。「この段落は動いたものを記述している」を grep するものは存在しない |

**一つの span が両方を担うことがあり、その二つは別々に判定する。**「ロールアウト計画は Notion を参照」は
ポインタでしかない。「Notion の計画のとおり、ロールアウトは3フェーズである」は、場所**と**内容の両方に
固定されている。計画が書き直されてもリンクは生き延びるが、この文は生き延びない。

**列は逆転しており、それこそが見る理由のすべてである。** 弱いほうが安いのは二重の意味においてで
ある：ツールがひとつ残らず見つけること、そして向こう側が、それを指しているテキストと同じセッションに
上がってくることがまれであり、不整合が対処されないまま座っているだけで済むこと。強いほうにはそのどちらの
性質もない。常に直す必要があり、そして誰も気づかない — その文は今も構文として通り、今もよく読め、書かれた
日とまったく同じだけ真に見えるからだ。

## The shapes on the page（ページ上の形）

| テキストが | 固定されている先 | 壊れるとき | 強さ |
|---|---|---|---|
| リンク、パス、行番号 | その場所 | 移動する | 弱 |
| issue / チケット / PR 番号 | その項目 | クローズ、移動、採番し直し | 弱 |
| 外部の出典の引用 | 他人の判断 | 相手が改訂する、または消える | 弱 |
| 散文の中で担われた名前 | その定義 | 改名、削除、意味の移動 | 強 |
| 員数、または完全だと主張された集合 | その成員 | 何かが加わる／抜ける | 強 |
| それが所有されている場所から写した定義や計画 | その所有者 | 所有者が変わり、この写しが変わらない | 強 |
| どう配置されているかについての主張 | その配置 | 再構成される | 強 |
| 翻訳、ミラー、二つ目のコピー | 原文の全体 | 原文のどこかが変わる | 強 |
| それが乗っているファイル自身についての宣言 | そのファイルの残りが述べていること | 宣言がカバーすべきものを本文が獲得する／失う | 強 |

**この一覧は閉じていない。** ここにない形でも、向こう側を直せばこちらも直さねばならないなら該当する —
その定義こそがテストであり、この表は定義のうち繰り返し現れる部分にすぎない。

### Spotting the strong ones（強いものをどう見つけるか）

強い依存は自分から名乗らない。目印を探すのではなく、文の形を読む。

- **固有名詞はすべて問いである：この名前は誰が所有しているか。** 答えが別のどこかなら、その文はその
  別のどこかに固定されている。
- **このファイルの外にあるものについての、現在形の主張はすべて** — 何をするか、何を含むか、どう
  組み立てられているか — そのものの現在の状態についての主張であり、状態が失効すれば一緒に失効する。
- **列挙はすべて。**「A と B」「三つのフェーズ」「各モジュール」：集合は、員数を言っていようがいまいが
  成員についての主張である。
- **向こう側を開いていなければ書けなかった文はすべて。** 写した定義の見分け方がこれである。書くのに
  出典を読む必要があったなら、真であり続けさせるのにも必要になる。
- **「〜に記載のとおり」「〜より」「〜と同じ」はすべて。** ポインタは弱だが、そのポインタの周りで
  その文が主張していることは、たいてい弱ではない。
- **両端が同じファイルの中にあることもある。** ヘッダが宣言し、本文が記述する。本文を編集すると、
  ヘッダだけがこのファイルのしていないことを述べたまま残りうる。ファイル境界を何も越えていないので、
  外部の何もそれを指摘しない — そしてヘッダは、本文をいじっている最中に読み返される見込みが最も低い
  部分である。

### What is not a dependency（依存ではないもの）

- その分野全体が共有している語彙。HTTP やマージコンフリクトを名指ししても、何も固定されない。
- そのページのために作った例で、外部の誰も所有していないもの — これは同時に、いま文書化している
  ツリーに対して書かれた例のほうが、そうでない例より精査に値する理由でもある。

## The pass（このスキルが行うこと）

1. **候補を読み出す。** 上に挙げた形に照らしてドキュメントを通し、強いものを読み取る。それを抽出して
   くれるものは何もないからである。
2. **矢印を確定する。** どちら側が動かねばならないかを述べ、逆向きも確認する：戻ってくる辺は、いま書いた
   ものの重複ではなく、それ自体が一つの項目である。
3. **グラフに組み上げる。** ノードは対象：このドキュメントと、それが触れているファイル・節・外部の出典。
   辺は `A → B` で、向きごとに一本。辺は、それを生んでいる span と、何の変更で発火するかと、その強さを担う。
4. **強い辺から先に報告する。**

span は根拠であり、呼び出し元が形を読み取るのはグラフからである — どのノードにすべてが向かって刺さって
いるか、どの対が互いを指し合っているか、どのノードには何も刺さっていないか。そのどれも span のリストからは
見えず、そしてそのどれもが次の一手を決める。

見つけた辺を返し、見つけなかったものについては何も言わない。「他に依存はない」と報告するパスは、持ちよう
のない網羅性を主張している。

## Common Rationalizations（よくある自己正当化）

| 自己正当化 | 実際のところ |
|---|---|
| 「依存はリンクだけだ。あとはただの散文だ。」 | 名前とは、読み手がクリックできず、保守する者が grep もできないリンクである。同じように壊れ、壊れたことをより告げない。 |
| 「これはただのリンクだから弱だ。」 | リンクは弱である。その文が向こう側に**ついて**述べていることは弱ではなく、しかも二つは同じ span に同居している。別々に判定しないと、強いほうが弱いほうの判定に乗って未報告のまま通る。 |
| 「向こう側は他人のシステムなのだから、こちらの心配ごとではない。」 | そこにこそ両方向の対が隠れている：一つの計画を二箇所が言い直しており、どちらのツールからももう一方が見えない。自力で表に出てくる見込みが最も低いということは、報告する理由であって、しない理由ではない。 |
| 「リンクチェックが通ったのだから、このドキュメントは問題ない。」 | 通ったのは、そもそも問題でなかったほうの半分である。ツールが見つけられる依存は、誰かがいずれ見つけたはずの依存である。常に直す必要があるほうは、読むことでしか見つからない。 |
| 「今は正確なのだから問題ない。」 | すべての依存は、書かれた時点では正確だった。秤にかけているのは、それが正確でなくなる日に何が起きるかである。 |
| 「これだけ列挙したらノイズになる。」 | そのグラフこそが findings である。ある項目が対処に値するかは呼び出し元の判断であり、あなたが濾し取った項目については彼らは判断できない。 |
| 「これは明らかに問題ないので、外しておく。」 | 「明らかに問題ない」は判定である。報告して、呼び出し元に同意させよ。 |
| 「ドキュメントの残りはきれいだと書き添えておく。」 | あなたが確認したものを確認しただけである。網羅性の主張はそれ自体が依存である — あなた自身の徹底ぶりへの依存であり、後から誰にも検証できない。 |
| 「span は全部挙がっている。矢印を引くのは見せ方の問題だ。」 | 矢印こそが findings である。span は二つのテキストが触れていることしか言わない。どちらが誤りになろうとしているのかを述べるのは向きだけであり、リストを渡された呼び出し元がそれを導出することはできない。 |

## Red Flags（危険信号）

- 「他に依存はない」と述べる報告 — 主張しえない網羅性である。
- span が引用ではなく言い換えられている。
- 辺を書くべきところに判定 —「これは古い」「落とすべき」— が書かれている。
- リンクしか見つけていない。ドキュメントを固定しているものの大半は散文である。
- 矢印の付かないまま報告された span、あるいは、動くのはどちら側かをどちらの端についても名指ししていない
  矢印。

## Verification（検証）

どのボックスも、それが捕まえるものが、呼び出し元をその報告に基づいて動けなくするか、その報告を検証
できなくするから、ここにある。残りの規則は、それが住んでいる場所で読まれることによって満たされる。

- [ ] どの辺も、どちら側が動かねばならないかを述べ、逆方向も確認されている。
- [ ] どの辺も、それを生んでいる span を引用として担っている。
- [ ] 強い辺が先頭に来ており、見つからなかったものについては何も主張していない。
