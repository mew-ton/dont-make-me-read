## Scope（範囲）

二つのテキストは、**一方を直したらもう一方も直さねばならない、さもなくば矛盾する**という関係にあるとき、
依存関係にある。リンクはその一つの形にすぎず、面白いほうの形ではない。

このスキルは、ドキュメントが**何に固定されているか**を報告する。判定はしない。依存は欠陥ではない — 何にも
依存しないドキュメントは何についても何も言っていない — そして、ある依存が保守コストに見合うかは「それが何を
買っているか」についての問いであり、それを握っているのは呼び出し元であって、このスキルではない。

## 二つの強さ、そして弱いほうが仕事の場所ではない理由

| | 弱 | 強 |
|---|---|---|
| 形 | ポインタ：リンク、パス、issue 番号、引用 | 散文：名前、記述、向こう側が何を言っているかの説明 |
| 直す必要があるか | 常にではない — ポインタは、指す先が変わっても生き延びうる | 常にある — その文は今や真でないことを述べている |
| どう見つかるか | 機械的に。リンクチェッカがひとつ残らず見つける | 読むことによって。「この段落は動いたものを記述している」を grep するものは存在しない |

**二つの性質は逆転しており、それこそが見る理由のすべてである。** 弱い依存は見つけるのが安く、放置しても
たいてい安全である。強い依存は常に直す必要があり、そして誰も気づかない — その文は今も構文として通り、今も
よく読め、書かれた日とまったく同じだけ真に見えるからだ。

だから**読む労力は強いほうに使う**。通りすがりに見た弱い依存は短く報告し、そこにパスを費やさない：リンクを
チェックするものが何であれ、その仕事ではあなたより優れている。

## What counts（何が該当するか）

| テキストが | 固定されている先 | 壊れるとき | 強さ |
|---|---|---|---|
| リンク、パス、行番号 | その場所 | 移動する | 弱 |
| issue / チケット / PR 番号 | その項目 | クローズ、移動、採番し直し | 弱 |
| 外部の出典の引用 | 他人の判断 | 相手が改訂する、または消える | 弱 |
| 散文の中で担われた名前 | その定義 | 改名、削除、意味の移動 | 強 |
| 員数、または完全だと主張された集合 | その成員 | 何かが加わる／抜ける | 強 |
| それを所有するファイルから写した定義 | その所有者 | 所有者が変わり、この写しが変わらない | 強 |
| どう配置されているかについての主張 | その配置 | 再構成される | 強 |
| 翻訳、ミラー、二つ目のコピー | 原文の全体 | 原文のどこかが変わる | 強 |

## Which end has to move（どちら側が動かねばならないか）

依存は片側にしか流れない：A を直せば B も直さねばならず、B を直しても A は放っておける。ドキュメントは
その両端のどちらかにおり、span の形はどちらなのかを教えてくれない。

**下流**なら、それは記述している：向こうが動けばこのテキストは誤りになる。**上流**なら、それは定義して
いる：向こうが従わねばならず、向こうが変わった日には、譲るべきだったのは向こうである。同じ文で、保守
コストは正反対になる。名前についていえば、それがドキュメントの定義する役割と、今それを満たしている実体
との違いのすべてであり、その項目がそもそも呼び出し元の注意に値するかを決める。

## What to return（何を返すか）

依存ごとに：その span、何に固定されているか、どんな変更で壊れるか、その強さ、そしてドキュメントが
どちら側にいるか。**強いほうから先に並べる。**span は説明せずに**引用する** — 呼び出し元が秤にかけるのは実際のその文であり、言い換えはそれ自体の
依存を持つ二つ目のコピーだからである。

見つけたものを返し、見つけなかったものについては何も言わない。「他に依存はない」と報告するパスは、持ちよう
のない網羅性を主張している。

## Common Rationalizations（よくある自己正当化）

| 自己正当化 | 実際のところ |
|---|---|
| 「依存はリンクだけだ。あとはただの散文だ。」 | 名前とは、読み手がクリックできず、保守する者が grep もできないリンクである。同じように壊れ、壊れたことをより告げない。 |
| 「リンクチェックが通ったのだから、このドキュメントは問題ない。」 | 通ったのは、そもそも問題でなかったほうの半分である。ツールが見つけられる依存は、誰かがいずれ見つけたはずの依存である。常に直す必要があるほうは、読むことでしか見つからない。 |
| 「今は正確なのだから問題ない。」 | すべての依存は、書かれた時点では正確だった。秤にかけているのは、それが正確でなくなる日に何が起きるかである。 |
| 「これだけ列挙したらノイズになる。」 | その一覧こそが findings である。ある項目が対処に値するかは呼び出し元の判断であり、あなたが濾し取った項目については彼らは判断できない。 |
| 「これは明らかに問題ないので、外しておく。」 | 「明らかに問題ない」は判定である。報告して、呼び出し元に同意させよ。 |
| 「ドキュメントの残りはきれいだと書き添えておく。」 | あなたが確認したものを確認しただけである。網羅性の主張はそれ自体が依存である — あなた自身の徹底ぶりへの依存であり、後から誰にも検証できない。 |

## Example: 壊れた後にしか気づけない強依存

コードがどこにあるかを記述したアーキテクチャドキュメント：

```markdown
## Layers

The parsing layer is `lexer` and `parser`. The analysis layer is `resolver` and `typeck`.
```
（訳：パース層は `lexer` と `parser`。解析層は `resolver` と `typeck`。）

この4つのモジュールはすべて、今やこのファイルと強依存の関係にある：一つ改名すればこのファイルは誤りになる。
5つ目も同様である — 誰かがそれを書いた日に。それは単に**欠けている**だけであり、この節は完全な答えのように
読まれ続ける。

ここには何もリンクされていないので、何もチェックしない。文は文法的に通り続け、自信を持ち続け、兆候を一切
出さない。これが見つかる経路は、貢献者がそれを信じて何かを間違った場所に置くこと — つまり、それが払わせる
はずだったコストをすでに払った後である。

**報告の形：** 上の span／二つの層の成員に固定されている／どのモジュールが追加・削除・改名されても壊れる／
強／ドキュメントは下流にいる — この中のどの名前も、ツリーが所有する実体の側である。

同じ節を、何も固定せずに書いたもの：

```markdown
## Layers

A module is in the parsing layer if it turns text into a tree without resolving a name, and in the
analysis layer if it resolves names against a tree it did not build.
```
（訳：名前を解決せずにテキストを木に変えるならパース層。自分が作っていない木に対して名前を解決するなら
解析層。）

新しいモジュールは自分で自分の居場所を決められるようになり、義務は向きを変えた：このファイルが層とは何かを
述べ、どちらの定義にも当てはまらないモジュールのほうが、譲るべきものになる。
