# 子スキルへ段階を委譲する

一つのスキルの一段階を別の場所で走らせるべきときに読むこと：自前のモデル、自前のツールセット、自前の文脈で。

## 何を委譲してよく、何をしてはならないか

委譲が決めるのは、**一つのフェーズがこの実行環境を離れるかどうか**である。委譲されたフェーズは依然として
親の作業であり、より安く狭いどこかで走り、それを
生んだ材料ではなく親が必要とするものを返す。

テストは、**呼び出し元が、その作業を検証するのに必要なすべてを受け取るかどうか**である。

**機械的で読み取り専用の収集、列挙、パースを委譲せよ** — PRのコメントの取得、変更ファイルの列挙、
パッケージレジストリの走査、設計をリポジトリに接地させること。これが通るのは、親が欲しかったのは答えだけで
あり、その答えは丸ごと戻ってくるからである。

**成果物を生み出すフェーズを委譲せよ。** 書かれたブリーフを一つ渡す。これが通るのは、成果物が丸ごと戻って
きて、読み手がその物自体を判断するからである。

**生み出すものが判定だけのフェーズは決して委譲しない。** レビューがその例である：その実質を子に置くと、
各判定が何に立脚しているかを欠いたまま戻ってきて、誰もそのレビューをレビューできなくなる。

## fork が何を買うのか、そして場合ごとに `model` と `background` が何を求めるか

以下の動機は fork が何を買うのかを述べるもので、上の委譲してよい二つのケースに当てはまる：収集はたいてい
`Context`、成果物を生み出すフェーズはたいてい `Cleanliness`、そして `Independence` はそのどちらかを二回委譲
する場合で、どちらの写しも他方の答えを見てはならない。

| 動機 | fork が買うもの | `model` | `background` |
|---|---|---|---|
| **Context** — 大量の収集をメインスレッドから外す | 生の材料が親の文脈に決して着地しない | それができる最安のモデル：純粋な収集と数え上げなら `haiku`、軽い正規化が絡むなら `sonnet` | `false`。親が同じターンで結論を使うため |
| **Independence** — 二つの子が互いの出力を見てはならない | `context: fork` は会話履歴を持ち込まないので、どちらの子も他方が生み出したものに届かない | `sonnet`。その作業が数え上げ以上を要するからである | 未設定のままにする — 既定は `true` — そうすれば並列に走る |
| **Cleanliness** — ブリーフを生み出した会話が成果物に届いてはならない | 探索、中途半端な依頼、取得した材料が、成果物が書かれる文脈に決して入らない | 未設定のままにする。作業は成果物自身のものである | `false`。呼び出し元が同じターンで結果を見せるため |

## Naming（命名）

`<parent-skill-name>-<role>`：親の名前、ハイフン、そして子が演じる役割 — `-change-inventory`、
`-repo-grounding`、`-version-lookup`。この接頭辞が、ディレクトリ一覧で親子を隣に並べる。そして対の改名は、
両方とも自分が所有する一回の編集である。

## The three fields every child carries（どの子も持つ三つのフィールド）

```yaml
user-invocable: false
disable-model-invocation: false
context: fork
```

`user-invocable: false` は子をユーザーの `/` メニューから隠す。

`background` が上のブロックに無いのは、その値が動機に従うからである。どの動機がどの値かは表の最後の列が
述べている。既定は `true` なので、`Context` と `Cleanliness` はどちらも `false` を設定する必要がある。

任意のフィールドが二つ、子をさらに狭める。`model` はコストと能力を天秤にかける：上の表のとおりに設定する。
`agent` はツールセットを選び（`Explore` と `Plan` は読み取り専用）、こちらが、理由を言えない限り外しておく
ほうである。成果物そのものを生み出す fork にとって、狭めることは誤りである：読み取り専用の
ツールセットでは書けないし、ファイルを列挙できる最安のモデルは、人が行動することになるものを起草させたい
モデルではない。両方を省けば fork は継承し、それが `Cleanliness` の行にとって正しい。

`disable-model-invocation: false` が、モデルから子への経路を開いたままにする。そしてここでの呼び出し元は
**モデル**である。

`context: fork` こそが、子を親のターンの延長ではなく実行環境にするものである。それがないと、`model` は現在の
ターンの残り — メインの会話 — に適用される。

## Passing input（入力の渡し方）

入力全体を **`$ARGUMENTS`** として渡す。複数行の自由形式のブリーフはそこでなら生き残り、添字付き引数や
名前付き引数が通るシェル的なクォート解析は生き残らない。
