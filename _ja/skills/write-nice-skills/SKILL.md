## Overview（概要）

このスキルは、`SKILL.md` 自身の frontmatter や本文における記法・規則や、本文が長くなった場合の分割の指針を
定める。これによって、以下の効果をもたらす。

- スキルの発動条件を的確にし、AI によるスキル利用の判断の精度を上げる
- スキルの指示・原則を、AI にサボらせず、指示を的確に行わせる
- スキルを読み込む際のトークンを節約し、他のスキルや指示のために文脈の余地を残す

## How to work（どう進めるか）

- **description と本文は、このスキルが定める記法に沿って書く。** それぞれを所有するファイルから取ること —
  下の表のとおりに。
- **スキル自身が消費するトークンを都度計測し**、重いスキルかどうかを都度判断する。計測はこのスキルの
  `scripts/count-tokens.sh` で行う。
- **記法が正しくても、それだけで手順が実行されるとは限らない。** AI がサボった場合は、記法に則ったうえで
  内容を改善する。

## Common Rationalizations（よくある自己正当化）

エージェントはこのスキルを飛ばす理由を探す：

| 自己正当化 | 実際のところ |
|---|---|
| 「description は短いほうが確実に発火する。」 | 発火は作業と共有された語によって起きる — プロンプトが供給する語か、作業そのものがすでに使っている語である。それが無ければ、長さがどうであろうと、そのスキルを作業に結びつけるものは何もない。 |
| 「自己説明的になるよう、手順を description に入れておく。」 | するとエージェントは description から行動し、本文を決してロードしない — あなたが書いた手順は飛ばされる。 |
| 「なぜその規則が重要かを description が説明しないと、誰も本気で受け取らない。」 | そのスキルが**何を**強制するかは description に属する。それを強制するのが*なぜ*正しいのか — 論拠、代償、代替案 — は本文のものである。両方を手渡されたエージェントは description から行動し、本文を決してロードしない。 |
| 「使わない場合を述べるのは否定的で、予算の無駄だ。」 | 適用される場合しか名指ししない description は、隣接する成果物にも発火し、誤った発火は毎回、本文まるごとを支払わせる。 |
| 「隣接する成果物を所有するスキルを名指しすれば、振り分けを助けられる。」 | それは「この成果物は自分のものか」に答えてしまい、エージェントはもう問わなくなる — そしてそれは、description がそもそも問わせるために存在する唯一の問いである。さらに他のスキルの名前を自分の description に書き込むことになり、相手が改名された日に、こちらが黙って誤りになる。 |
| 「1ファイルのほうが複数より単純だ。」 | 肥大した `SKILL.md` は、そのスキルが発火する*たびに*ロードされ、文脈全体を引きずる。同梱ファイルはそれを必要とする枝でだけ読まれる。 |
| 「今フルのガイドを書いて、後で削る。」 | 削らない。長すぎるスキルは長すぎるまま出荷される。 |
| 「これは自分には良く読める。」 | あなたは読みながら、テキストに欠けている意図を自分で補っている。作業が供給する語と、スクリプトが報告する数字に照らして確認せよ。 |

## Red Flags（危険信号）

- 他のファイルを一つも開かずに、著者がスキルを仕上げられてしまう `SKILL.md`。
- description が手順、適用する判定基準、あるいは他のスキルの名前を担っている。
- description の頭がタグ列か、キーワードの羅列になっている。
- 同梱ファイルが別の同梱ファイルから到達されている。
- 本文の最初の一文が、そのスキルが何をするかを述べていない。

## Verification（検証）

各項目がここにあるのは、それが捕まえるものがスキルを機能させなくするか、あるいはそれが予算であるからである。
規則そのものは、それが住んでいる場所で読まれることによって満たされる。

- [ ] frontmatter が解析でき、`name` がそのスキルの置かれたディレクトリと一致する。
- [ ] description の本文のどこにも `<` も `>` も無い — さもなくば何もロードされない。
- [ ] description が1024文字以内である。
- [ ] そのスキルが一つの成果物または一つの枝のためにロードするファイルすべてに対して、`count-tokens.sh` がゼロ終了する。
- [ ] それが常時オンなら：それ自身と、一緒に出荷する常時オンの `SKILL.md` すべてに `count-tokens.sh` をかけ、数を足し合わせて2000未満。
- [ ] そのスキルに到達すべきケースが実際に到達する — インストールした状態と、していない状態の両方で走らせ、description が到達させたケースと、モデルが元から処理できたケースを区別する。
- [ ] Common Rationalizations と Red Flags が `SKILL.md` そのものにあり、エージェントが何も開かずにそれに出会える。
- [ ] そのスキルがロードするどのファイルも、`SKILL.md` から直接、明示された条件または問いのもとで指されている。
