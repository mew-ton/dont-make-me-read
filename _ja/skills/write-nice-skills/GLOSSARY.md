# Glossary — write-nice-skills

`SKILL.md` と、それが振り分ける先のファイルが厳密に使う用語。各項目は語の意味だけを述べる。それを使う
ルールは、そのルールを所有するファイルにある。

**Leading word（先導語）** — スキルが必要とされるときに現れ、かつそのスキルの `description` にも現れる語。
人がそれを求めるときに打つもの、あるいは — プロンプトなしで作業の途中に発火するスキルにとっては —
作業そのものがすでにそれをそう呼んでいるもの。

**Bound（境界）** — スキルが発火しては*ならない*条件。その occasion を否定した形、すなわち
「Does not apply when …」で書く。

**Reach clause（到達節）** — `description` のうち、二つ目の入口を認める部分。このスキルが持つ規則を別の
スキルが必要とすることを、スキル名ではなく必要として名指しする。

**Occasion（機会）** — 書かれている成果物、または進行中の活動。何がそのスキルを呼び込むのかとして
`description` に記す。

**Branch（枝）** — そのスキルが扱う一つの別個の状況。異なる枝はスキルの異なる部分を読む。その違いこそが、
reference を切り出すことを正当化する。

**Child skill（子スキル）** — 親スキルが、一つのフェーズを固有の実行環境（`context: fork`）で走らせる
ために起動するスキル。それを導いた材料ではなく、親が必要とするものを返す。

**Progressive disclosure（漸進的開示）** — `SKILL.md` から材料を出して context pointer の後ろへ置き、
常時ロードされる中核を小さく保つこと。

**Context pointer（文脈ポインタ）** — `SKILL.md` の中の、条件とファイルを名指す一行。その条件が満たされる
まで reference はロードされない。

**No-op（無効果の指示）** — モデルが指示されずともすでに従っている指示。読み手にとっては、何かを変える
ルールと同じだけのコストがかかる。

**Common Rationalizations** — エージェントがスキルを飛ばすために使う言い訳の表。それぞれに、それを論駁する
実際のところが対になっている。
