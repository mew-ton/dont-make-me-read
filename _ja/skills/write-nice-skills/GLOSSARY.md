# Glossary — write-nice-skills

このスキルの `SKILL.md` と、それが振り分ける先のファイルが厳密に使う用語。各項目は語の意味だけを述べる。
それを使うルールは、そのルールを所有するファイルにある。

**Leading word（先導語）** — スキルが必要とされるときに現れ、かつそのスキルの `description` にも現れる語。
人がそれを求めるときに打つもの、あるいは — プロンプトなしで作業の途中に発火するスキルにとっては —
作業そのものがすでにそれをそう呼んでいるもの。

**The work（作業）** — スキルが発火しうるとき、エージェントが取り組んでいる成果物と活動：目の前の diff や
ファイル、途中まで進めているタスク。与えられたプロンプトはそれとは別であり、スキルが発火する語はどちらからも
供給されうる。

**Intent（意図）** — その著者が何を強制したかったのか。著者自身がそれを言うときの言葉で。

**Occasion（機会）** — 書かれている成果物、または進行中の活動。何がそのスキルを呼び込むのかとして
`description` に記す。

**Bound（境界）** — スキルが発火しては*ならない*条件。

**Reach clause（到達節）** — `description` のうち、別のスキルがこのスキルの規則を必要とすることを名指し
して、二つ目の入口を認める部分。

**Always-on skill（常時オンのスキル）** — 本文が、それをロードしたレスポンスを越えて効かせ続けるスキル。
一つの成果物のためではなく、ある活動のあいだ常駐する。

**Branch（枝）** — そのスキルが扱う一つの別個の状況。異なる枝はスキルの異なる部分を読む。

**Child skill（子スキル）** — 親スキルが、一つのフェーズを固有の実行環境（`context: fork`）で走らせる
ために起動するスキル。親が必要とするものを返す。

**Progressive disclosure（漸進的開示）** — `SKILL.md` から材料を出して context pointer の後ろへ置き、
常時ロードされる中核を小さく保つこと。

**Context pointer（文脈ポインタ）** — `SKILL.md` の中の、ファイルと、そこへ到達する条件または問いを名指す
一行。読み手がその場合に入るまで reference はロードされない。

**No-op（無効果の指示）** — モデルが指示されずともすでに従っている指示。
