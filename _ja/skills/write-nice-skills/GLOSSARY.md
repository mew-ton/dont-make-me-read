# Glossary — write-nice-skills

スキルのオーサリングについて語るための共有語彙。`SKILL.md` と、それが振り分ける先のすべてのファイルは、
これらの用語を厳密に使う。

**Leading word（先導語）** — スキルが必要とされるときに現れ、かつそのスキルの `description` にも現れる語。
人がそれを求めるときに打つもの、あるいは — プロンプトなしで作業の途中に発火するスキルにとっては —
**作業そのものがすでにそれをそう呼んでいる**もの。その共有された語こそが両者を結びつけ、スキルを発火させる。
だから description の先頭に置かれる。それは作業そのものが産む語であり、自然な文の中に置かれる。

**Trigger（トリガー）** — スキルを起動すべき条件。「applies when …」の形で述べる。枝ごとに一つ：同じ枝を
言い換えただけの同義語は重複である。

**Branch（枝）** — そのスキルが扱う一つの別個の状況。異なる枝はスキルの異なる部分を読む。その違いこそが、
reference を切り出すことを正当化する。

**Child skill（子スキル）** — 親スキルが、一つのフェーズを固有の実行環境（`context: fork`）で走らせる
ために起動するスキル。収集した材料ではなく結論を返す。

**Progressive disclosure（漸進的開示）** — 参照材料を階層の*下*へ移すこと：`SKILL.md` から出して context
pointer の後ろへ置き、常時ロードされる中核を小さく保つ。すべての経路が必要とするものをインラインにし、
一部の枝しか到達しないものを開示にする。

**Context pointer（文脈ポインタ）** — `SKILL.md` の中のリンク（例：「For X, see `references/x.md`」）で、
その reference をいつどこでロードすべきかをエージェントに伝えるもの。ポインタの条件が満たされるまで
reference はロードされない。

**Common Rationalizations** — エージェントがスキルを飛ばすために使う言い訳の表。それぞれに、それを論駁する
実際のところが対になっている。
