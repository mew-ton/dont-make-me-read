# dont-make-me-read — なぜ存在するのか

このスキルを保守する人のために。このファイルは何にもロードされない：`SKILL.md` から参照されていないので、
エージェントの文脈を一切消費しない。それがこのファイルの目的である。

## 二つの命題

このプラグインのすべての規則はここから導かれる。

1. **何をすべきか割り出すために、頭の中に多くを抱えたい者はいない。** 美しいテキストのためでも、網羅的な
   テキストのためでも、礼儀正しいテキストのためでもない。
2. **書き手には、それがどれだけかを判定できない。** 自分の草稿は、欠けている文脈を自分で補いながら読むので、
   その範囲は自分にとってだけ小さく読める。

## なぜこれらが advice ではなく skill なのか

二つ目の命題がその理由のすべてである。advice を受け取るのは、すでに問題が見えている者である。そして書き手に
この問題は見えない — 草稿は本人には十分に読め、どれだけ眺めていても十分に読めたままである。

だから判断は、書いているその瞬間の外側から到来しなければならない。それが、consult されるスタイルガイドでは
なく作業の途中で発火する skill である理由であり、このうち幾つかが「すでに書かれたテキストに対して走らせる」
ためだけに存在する理由でもある。

## なぜ実務側の半分はここではなくガードにあるのか

`SKILL.md` は「あなたは読みながら、テキストに欠けている意図を自分で補っている」を Common Rationalizations に
置いている。そこにあれば、エージェントがその言い訳に手を伸ばしたその瞬間に反駁する。ここで命題として述べれば、
一度読まれて同意されるだけであり、それは適用されることとは違う。
