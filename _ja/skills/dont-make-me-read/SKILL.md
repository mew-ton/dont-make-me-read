## Overview（概要）

このスキルは、行動の対象として書かれたものすべてを、その読み手が行動する前に抱えねばならない最も狭い
範囲まで抑え込む：自分がどれだけを求めているかを判別できない唯一の人間が、書き手である。

## The range（範囲）

範囲とは、読み手が目の前のものに基づいて行動するために抱えねばならないもののすべてである。読んでいる
ものの長さとは別物である：二つの別ファイルを開いて初めて意味を持つ短い段落は、広い範囲を持つ。

| 何が壊れたか | 読み手が払うもの | 直し方 |
|---|---|---|
| 範囲の中に、判断に関わらないものがある | それを読み、それに基づいて確信を持って判断する | 削る |
| 範囲が、この読み手には到底たどり着けない先へ伸びている | 行き止まり | 削る |
| 範囲が、たどり着ける先へ伸びていて、行かねばならない | 往復 | 必要な部分をここに述べる |

コードでは、往復の直し方が逆向きになる：呼び出し元が知っていることを述べ直すモジュールは、呼び出し元への
依存を引き受け、以後に加わる呼び出し元もすべてその範囲の内側に入る。代わりに知識を外へ出すこと。

## Which file to read（どのファイルを読むか）

| 問い | 読むもの |
|---|---|
| テキストが、読み手の到達できないもの — 議論、レビュー、過去の状態 — に寄りかかっている | [`rules/unverifiable-context.md`](rules/unverifiable-context.md) |
| テキストが、読み手を到達できる別の場所へ送っている | [`rules/reference-detours.md`](rules/reference-detours.md) |
| 呼び出し元が二つ以上あるコード、あるいはその間のインタフェース | [`rules/caller-knowledge.md`](rules/caller-knowledge.md) |
| テキストが仕上がった | [`VERIFICATION.md`](VERIFICATION.md) |

## The test（テスト）

範囲のあらゆる粒度において — 単語、文、セクション、ファイル：

> **これは読み手が次にすることを変えるか。**

変えない：削る。変えるのに欠けている：足す。短いことも長いことも結果であって、目的では決してない。

ノイズが払わせるのは読む時間ではない。**確信を持ってなされる誤った判断**である — そして読み手は人間か
エージェント、常に両方であり、両者は同じようには失敗しない：

| ノイズ | 読み手が結論すること |
|---|---|
| 自分で重みづけできたはずの修正案のメニュー | 選択は自分のものだ — 書き手より少ない情報で決めることになる |
| たまたまサンプルしたパスを、修正箇所として示したもの | エージェント：それらのファイルが触るべき集合のすべてだ。人間：「少なくともこれら」 |
| 「適切に処理する」 | 仕様は完全だ |
| issue に書かれた実装方法 | 書き手が見た構造が今日もその構造のままだ |

## What must never be cut（決して削ってはならないもの）

判断が依存していて、かつ読み手が再構成できないもの：

- 仕様や設計の背後にある根拠 — ビジネス要件、規制、ドメイン制約、プロダクトの決定
- 明らかな誤った一手を排除する制約。読み手に差し出される選択肢としてではなく、彼らがぶつかることになる
  壁として述べること
- そもそもその依頼を正当なものにしている事実

これらを削ることは範囲を狭めない。判断材料の少ない者に判断を手渡すことである。読むのに高くつき、かつ
判断がそれを必要とする行は、残る。長さの上限が効くのは、何をすべきか知るために読み手が必ず通る経路にだけ
である — 実例、証拠、ポインタの指す先の原典といった裏付けとなる資料は、それを必要とする者が取りに行く
ものであり、上限はかからない。

## Persistence（効力の持続）

ロードされたあとは、それをロードしたレスポンスだけでなく、すべてのレスポンスで効力を持ち、ルールファイルも
一度読まれたら同じである。これから書く
ものが誰かの行動の対象になるかどうか迷っているあいだも、効力は残る。解除されるのは、作業が誰も行動の
ために読まないものへ移ったとき、または止めるよう言われたときである。

## Common Rationalizations（よくある自己正当化）

| 自己正当化 | 実際 |
|---|---|
| 「原則は分かったので、成果物のルールなしで書ける。」 | 原則は何を狙うかを言うだけで、その成果物が何を含まねばならないか — セクション一覧、予算、ゲート — は決して言わない。そちらもロードすること。 |
| 「短いほうが良いのだから削る。」 | 削ることは二つある結果の一方であり、もう一方は、判断が必要とするものを足すことである。その行がどちらなのかを問うこと。 |
| 「文脈は多いほうが安全だ。」 | 判断が使わない文脈こそが、読み手に誤ったことを確信させるものである。 |
| 「これはテキストではなくコードなので、範囲の話は関係ない。」 | コードは変更される前に、それが依存しているものを抱えた者に読まれる。 |
| 「自分が読む分には問題ない。」 | 読みながら、テキストに欠けている意図を自分で補っている。テキストしか持たない者として判断すること — それがこの失敗モードのすべてである。 |
| 「到達できるのだから、そこを指すので十分だ。」 | 到達できるかどうかにかかわらず、そこへ送られることが代金である。 |
| 「ただのコメント／コミットメッセージ／issue であって、ドキュメントではない。」 | テストはそれがスレッドより長生きするかどうかであって、何と呼ばれているかではない。 |
| 「共通関数にフラグを足すほうが差分が小さい。」 | 今日は。以後、callee は呼び出し元一つにつき一度ずつ編集される。 |
| 「しばらく効力を持っていたのだから、役目は果たした。」 | これは毎レスポンス取り直される。効力が切れたそのターンが、誰も行動できない段落を書くターンである。 |

## Red Flags（危険信号）

- 別のファイルを開いて初めて意味を持つ文：「上記参照」「config と同じ」。
- 「議論したとおり」「当初は X でいくつもりだった」「A ではなく B」：参加者にしか辿れない過去。
- 呼び出し元の名前でしか正直に名づけられない引数：`isDetailPage`、`from: 'pageA'`。
- 真であるから残っている段落 — 読み手が次にすることを変えるから残っているのではない。
- 制約が、読み手がぶつかる壁としてではなく「こうすることもできる」という選択肢として書かれている。
- 短くなった代わりに、論拠・制約・その依頼を正当化する事実のどれかが消えた草稿。
