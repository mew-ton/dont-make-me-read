# この規則がどこから来たのか

このファイルを指すものは何も無く、指すべきでもない：これはスキルを保守する者に向けた出自と設計上の論拠で
あって、アーキテクチャドキュメントを書くエージェントがロードしなければならない材料ではない。ここに置くこと
で本文の外に出せる。本文にあれば、ドキュメントを書きたいだけの読み手全員が代金を払うことになる。

## このスキルが何を拡張しているか

`SKILL.md` の「What the doc owes its reader」にあるセクションは **matklad の `ARCHITECTURE.md`**
（Alex Kladov, 2021）のものであり、ここに挙げる恒常ルールも同じである：短く保ち頻繁には変わらないものだけを
書く、重要なファイル・モジュール・型はその中へリンクせず名前で挙げる、不変条件を明示する。彼の形は決着して
おり、このスキルはそれを蒸し返さない。

このスキルが足すのは、案内される側ではなく**足す側**の読み手である：各セクションは、そのドキュメントが見た
ことのない事例も置けるように書かれる。「The rules」の下の条件はそこから来ている — 実体ではなく役割、不変条件
の上のゴールデンルール、全体を覆う分類、他のファイルが所有する定義 — そして「不変条件を明示せよ」を繰り返す
のではなく、テスト可能な問いへ研いでいるのもそのためである。

向きのテストの背後にある腐敗の議論は、matklad のリンクのルールを一歩内側へ入れたものである：それを所有する
ファイルからコピーした定義は、リンクとまったく同じように腐り、どちらの失敗も自分からは名乗り出ない。

## 近隣のスキルとの関係

本文がもう明示しない関係である。名指ししても著者の行動が変わらなかったからだが、次にこのスキルを編集する
者のために記録しておく。

- `dont-make-me-read` — このスキルが鋭くしているテスト。そして制約を「読み手がぶつかることになる壁として」
  述べるルールの出どころ。
- `dont-make-me-read` の `rules/unverifiable-context.md` — 根拠を残しつつ審議を締め出すもの。
- `dont-make-me-read` の `rules/reference-detours.md` — 使用地点で何を言い直してよいかを決着させるもの。このスキルはそれを、他の
  ファイルが所有する定義について狭めている。
- `find-document-dependencies` — 矢印を引くもの。保守側のテストを目視ではなく実行できるようにする。
- `write-nice-skills` — `SKILL.md` はエージェントへの指示であってアーキテクチャドキュメントではない。その
  境界は各スキル自身の description が決着させており、どちらの本文にも条項を要さない。
