## Overview（概要）

行動せずに同意できてしまう規則は規則ではない。そして著者にはその違いが感じ取れない — 自分はどの行動のこと
かをすでに知っているからである。効力を持ち続ける規則はまた、順番どおりに読まれない。だから各項目は、書かれた
場所ではなく目が落ちた場所で機能しなければならない。

## DO

- **各規則を命令形で述べること。** 読み手が行動するのは動詞に対してであり、その動詞が解く問題の記述に対して
  ではない。
- **まず指示を、次にそれを狭める制約を書くこと** — 「事実を使用地点で述べよ」、そして「原典はその場に残せ」。
- **指示と禁止がどちらも複数あるなら、DO のリストと DON'T のリストに分けること。** そうすれば極性は、読み手が
  読み飛ばせる一語ではなく構造のほうに載り、それぞれが幾つあるかも散文を解析せずに見える。
- **一つの項目を狭める制約や例外は、その項目の行に置くこと。** そうすればその対は、その行に着地して上を何も
  読まない読み手のもとでも生き残る。
- **代償は同じ項目の中に、一節で収まる形で与えること。** 代償が見えない規則は、圧力がかかったとき最初に
  落とされる。

## DON'T

- **制約を説明して、行動をそこから推論させること。** それがこのスキルが存在する理由である失敗であり、しかも
  完成した散文として読める。
- **項目の見出しを言い直してから条件を付けること。** 一つの文を二層にすることが、一行の規則を段落にする。
- **後から項目が挿入されるものに番号を振ること。** 番号は動く住所であり、その項目自身の冒頭の語は動かない
  住所である。
- **規則の理由を、その規則以外の場所に置くこと。** ポインタの後ろにある理由は、規則が破られているその瞬間に
  誰にも読まれない。
- **誰にも違反できない項目を残すこと。** 違反する方法のない規則は現状の記述であり、破れる規則のほうを薄める。

## Common Rationalizations（よくある自己正当化）

| 自己正当化 | 実際のところ |
|---|---|
| 「理屈を先に置かないと、規則が恣意的に見える。」 | 理屈に同意した読み手も、何を打てばいいかはまだ知らない。命令形を与え、理由は同じ項目の中に置け。 |
| 「DON'T のリストは否定的だから、全部 DO の形で書く。」 | すると禁止はすべて裏返しで届き、読み手が裏返し直す — しかも下手に。「X せよ」と「Y するな」は別の主張である。一方しか担っていないドキュメントは、規則の半分を欠いている。 |
| 「一つの段落にまとめれば、関連する規則が近くに置ける。」 | 区別がつかなくなるだけである。段落の途中に着地した読み手は、目の前に規則が幾つあるか分からず、次に編集する者にも分からない。 |
| 「番号を振れば規則を引用できる。」 | 一つ挿入されるまでの話であり、そのあと引用はすべて一つずれる。引用に足るのはその項目自身の語であり、そちらは正しいままである。 |
| 「これは自分には明確に読める。」 | あなたはその文を読む前から、どの行動のことかを知っていた。それこそが読み手の持たない唯一のものである。 |

## Red Flags（危険信号）

- 制約を説明して、行動を推論に委ねている項目。
- DO の項目の中に禁止が埋まっている。
- 後から項目が挿入されるリストに番号が振られている。
- 誰にも違反できない項目。

## Verification（検証）

- [ ] どの項目も命令形で始まっている。
- [ ] どの制約・例外も、それが狭める項目の行に置かれている。
- [ ] どの項目も代償を担っているか、なぜ存在するのかが読み手に見えている。
