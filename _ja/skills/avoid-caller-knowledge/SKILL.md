## Why this exists（なぜこれが存在するのか）

関数を読む者は、それを変更する前に、それが依存しているものを抱えねばならない。**誰が呼んだか**から何を
するか決める関数は、すべての呼び出し元をその範囲に入れ、次の呼び出し元もそこに入れる。

言い直しがそれを修復しない場所こそがコードである。テキストは読み手が必要とするものを使用地点で繰り返せて、
原典は権威のまま残る。何も実行されないからである。呼び出し元の知識を引き受けた callee は何も複製しない —
その呼び出し元への依存を、恒久的に引き受ける。

## The rule（ルール）

**知識は中へ持ち込むのではなく、外へ出す。** 呼び出し元どうしで違うものは、呼び出し元が述べるべきもので
ある。callee はそれをデータとして受け取り、誰が渡したかを知らない。

裏付けとなる症状：共通化は変更を安くするはずだったのに、実際には呼び出し元が増えるたびに共通コードが
編集されている。

## The signal is in the name（兆候は名前に出る）

その引数を、その関数が実際にしていることの語彙で名前を付け直してみる。生き延びるなら callee 自身のもので
ある。正直に付けられる唯一の名前が呼び出し元の同一性なら、知識は越境している。

| 引数 | 何と読めるか | 判定 |
|---|---|---|
| `scope: 'own' \| 'team'` | そのクエリが覆う範囲 | callee 自身のもの |
| `currency: Currency` | その金額が何建てか | callee 自身のもの |
| `from: 'pageA' \| 'pageB'` | 誰が尋ねているか | 越境 |
| `isDetailPage: boolean` | 呼び出し元がどこに住んでいるか | 越境 |
| `variant: 'list' \| 'detail'` | どの画面がそれを描画するか | 実際に違うものの名前（`density`、`showsSummary`）に付け直すまでは越境 |

テストは名前であって、分岐の数ではない。callee は自分が所有する事実でならいくらでも分岐してよい。

## When this is not the finding（これが指摘でない場合）

- 違いが**本当にドメインデータ**であり、それを指すドメインの語が存在する。それを渡す。
- 二つの呼び出し元はもともと同じことをしていなかった。そのとき解くべきは引数ではなく共通化のほうである —
  素直な関数二つのほうが、両方に仕える一つより読むのが安い。
- 呼び出し元の同一性そのものが主題である場合：ロガーの `source`、メトリクスのラベル、監査記録の実行者。
  何もそれで分岐していない。それは参照されているのではなく、運ばれている。

## Persistence（効力の持続）

ロードされたあとは、それをロードしたレスポンスだけでなく、すべてのレスポンスで効力を持つ。ある引数が
呼び出し元を名指ししているのかドメインを名指ししているのか迷っているあいだも、効力は残る。解除されるのは、
作業がコード以外へ移ったとき、または止めるよう言われたときである。

## Common Rationalizations（よくある自己正当化）

| 自己正当化 | 実際 |
|---|---|
| 「共通関数にフラグを一つ足すほうが、呼び出し元を両方直すより差分が小さい。」 | 小さいのは今日だけである。そのフラグは両方の呼び出し元を callee の範囲に入れ、次の呼び出し元も入れる。以後、共通関数は呼び出し元一つにつき一度ずつ編集される — 避けたはずの差分が、何度も届く。 |
| 「同じエンドポイントを叩くのだから、ロジックは一箇所にあるべきだ。」 | 呼び出しを共有していることは、判断を共有していることではない。呼び出しは共有したまま、判断はその理由を持っている側へ返す。 |
| 「値が二つしかない引数なので、本物の結合ではない。」 | 結合はユニオンの大きさでは測らない。両方の呼び出し元が callee の型に名指しされており、どちらも callee に触れずには改名も分割も削除もできない。 |
| 「そうしないと呼び出し元が渡す引数が多くなる。」 | その並びこそが、違いの実体である。長い引数列は読める。呼び出し元の形をしたフラグは、同じ情報を読み手に見えない場所へ隠す。 |
| 「今回だけ呼び出し元の同一性を渡して分岐する。」 | 二度目がそれをパターンにし、二度目は必ず来る — 共通モジュールとはそういうものである。 |

## Red Flags（危険信号）

- 呼び出し元の名前でしか正直に名づけられない引数：`isDetailPage`、`from: 'pageA'`、画面の名前がついた
  `variant`。
- 呼び出し元が増えるたびに、共有された関数が編集されている。
- 呼び出し元を開かないと読み手が評価できない分岐。

## Verification（検証）

- [ ] どの引数も、その callee がすることの語彙へ改名しても生き残る。
- [ ] 呼び出し元を足しても、callee の中を編集する必要がない。
- [ ] 残っている分岐はどれも、誰が呼んだかではなくドメインのデータによる。
