# dont-make-me-read

他人が行動する前に読まねばならない文章 — GitHub issue、PR のレビュー指摘、ドキュメント、`SKILL.md`、
コードコメント、コードそのもの — のための [Claude Code](https://claude.com/claude-code) プラグイン。

その文章の代償は長さではない。読み手が「何をすればいいか」に至るまでに頭の中で抱えねばならない量であり、
書き手にはそれが感じられない：自分の下書きは、そこに書かれていないものを自分で補いながら読むので、
自分にだけは明快に読める。だからこれは、思い出して適用する助言ではなく、書いている最中にロードされる
ルールとして配られている。ルールは、別の作業の途中で走り書きされたコメント — それを最も必要とし、かつ
誰も立ち止まってレビューしない文章 — にまで届く。

代償を払う読み手は、人間かエージェントである。どちらも文脈を集める側であり、どちらも最終的に抱えたもので
行動する。

## Install

まだ marketplace には登録されていない。リポジトリを clone して、Claude Code をそのチェックアウトに向ける：

```bash
git clone https://github.com/mew-ton/dont-make-me-read.git
claude --plugin-dir ./dont-make-me-read
```

## Commands

利用者に向いている面は、コマンドがすべてである。

| Command | こういうときに選ぶ |
|---|---|
| `/write-issue` | 問題を誰かに手渡そうとしていて、その人はあなた抜きで行動することになる |
| `/write-review-comment` | PR で何かを見つけ、往復なしで修正まで届かせたい |
| `/write-skill` | `SKILL.md` を書いている、または改稿している |
| `/write-architecture` | いまコードを読んで下した判断を、次の貢献者がもう一度下すことになる |
| `/write-readme` | 誰かが何も知らずにこのプロジェクトに辿り着き、これが自分のものかを判断することになる |
| `/review-issue` | issue はすでに書かれていて、そのままで行動できるかを知りたい |
| `/review-text` | PR が上がっていて、その説明文と変更するコメントを、あなたの文脈を一切持たない者に読ませたい — 必要ならレビューコメントとして投稿させる |

writing コマンドは、まだ決着していないものを決着させ — 既存 issue の取得、まだ開いている点の質問、
そもそも指摘が何なのかの特定 — 一つのブリーフを、その成果物を所有するスキルに手渡す。ブリーフを生み出した
やり取りは、書かれるものに一切入らない。

## Skills

スキル名を打つことはない。スキルは、モデルが書いている最中に自分の判断でロードし、上のコマンドは必要な
ものを呼ぶ。

スキルの名前は動詞で始まり、その動詞が働く向きである：あなたの文章に何を供給するのか、何を取り除くのか、
あるいは何かに判断させるための材料を集めるのか。それらすべての下に `dont-make-me-read` が立っている。
何かが書かれている間つねに効いていて、読み手が抱えねばならない範囲と、それが読み手に課す代償を担う。

## Language

スキルは英語で書かれている。公開されたプラグインは、利用者がどの言語でプロンプトを書くか知りようがない
からである。スキルがあなたに**何語で書け**と言うかは別の問題で、答えはどれも同じ：issue も指摘も
ドキュメントも、その読み手がすでに使っている言語で、かつ一つの言語だけで書く。

## Architecture

このプラグイン自身の形についての判断を決着させるもの — 新しい入口をどこに置くか、スキルがどの文脈で
走るか、どのツールを持つか — は [`ARCHITECTURE.md`](ARCHITECTURE.md) にある。
